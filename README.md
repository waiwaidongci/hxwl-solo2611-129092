# 海岬批发市场到货缺报早班日报

`hxwl-solo2611-12` · 定时分发与发布门槛

仓点按卸货排班登记各品类的应报计划，卸货口按到货批次回传收货回执。早班值班员在北京时间 06:30 对账，确定哪些仓点要催报，以及日报能否进入站内收件箱。

## 模拟客户与工作流

海岬农副产品批发市场早班调度室（模拟运营团队，覆盖北、东、南 3 个片区和 6 个收货仓）

- 值班员逐个翻仓点群核查回执，零到货和未上报经常混在一起。
- 补报覆盖前一版 Excel，次日复盘时还原不了 06:30 的收报情况。
- 日报发到全员群，缺报仓点的片区协调员容易错过催报任务。

值班主管根据放行结论排入站内日报分发。早班调度室收全场明细，出现缺报的片区协调组核对并催收对应仓点和品类。拦截时由值班员按缺报名单先催齐，再复核发布。

## 业务模块

- 早班收货台账
- 截点与发布门槛
- 收报差异与催报名单
- 日报分发与收件箱

## 计算口径

每天每个片区的仓点和品类组合应有一条计划，可另有一条到货回执。截点前或恰好在截点收到的回执计为实报，零到货也算已报。收报完整率＝实报条数 ÷ 应报条数。全场与各有计划片区按未四舍五入的比例过门槛。当日无计划时拦截。计划来自卸货班表，若源台账漏排整条计划，系统无法推断应报项，导入前须由班组核对排班。

样例输入为 `海岬到货早班台账_20261124-25.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 11 月 24 日 04:00，调度室把 6 个收货仓的 24 条应报计划纳入早班台账。演示文件同时含 11 月 25 日的记录。
2. 05:51，东区沿海仓的水产回执填报到货 0 批，仍算 1 条实报。
3. 06:30，截点当分钟收到的回执纳入日报。全场应报 24 条、实报 22 条，完整率为 91.67%。
4. 值班员从缺报名单定位北区新桥仓叶菜和南区临江仓水产，由两个片区协调组催报。
5. 85% 门槛下，各片区均达标，日报可进入站内收件箱。改用 95% 复核时，发布被拦截。
6. 06:42，新桥仓收到叶菜补报。用 06:42 重算可纳入补报，原 06:30 日报仍保留该缺报项。
7. 11 月 25 日 06:30，每日计划对下一业务日重新计算。当天应报 24 条、实报 23 条。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18321`，API `http://127.0.0.1:19321`，数据库宿主端口 `17821`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 MySQL 8.0 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
